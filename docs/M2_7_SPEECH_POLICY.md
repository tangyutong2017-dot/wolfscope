# M2-7 发言长度策略

## 目标

降低警上和白天发言的模板堆叠与 token 消耗，但不规定发言内容结构，不要求固定的“身份—分析—票向”模板。

## 分阶段限制

| 任务 | 建议字符数 | 硬上限 |
|---|---:|---:|
| 警长竞选 | 160–220 | 280 |
| 普通白天发言 | 140–220 | 300 |
| PK 发言 | 100–160 | 220 |
| 放逐遗言 | 120–200 | 260 |
| 首夜死亡遗言 | 80–150 | 200 |

字符数按 Python `len()` 统计处理后的中文文本。建议区间只进入 Prompt，不作为 Schema 拒绝条件；因此稍短或稍长的有效发言不会引发模型格式修复。

## 硬上限处理

`SpeechPolicy` 在模型决策通过 Schema、Evidence 和 Strategy 审计后执行。未超过上限时原样保留；超过上限时优先在上限前最近的中文句末标点处结束。如果可用句末位置过早，则保留到硬上限前一字符并添加省略号。该过程不再次调用模型，也不向 Agent 注入内容结构。

每次发言调用在 `ModelCallRecord` 中记录：

- `speech_original_chars`
- `speech_final_chars`
- `speech_truncated`

完整局诊断汇总 `speech_truncations`，用于 M3 比较不同模型、temperature 和 Prompt 下的长度服从度。
