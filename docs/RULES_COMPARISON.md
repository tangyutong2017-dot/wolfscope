# WolfScope 九人局规则对照与建议

> 状态：Accepted，WolfScope Rule Baseline v1.0
> 日期：2026-08-06
> 对照对象：第一版 `狼人杀` 与参考仓库 `AIWolfGame`

## 1. 结论摘要

WolfScope 不应完整复制任一实现。建议以第一版的确定性裁判和严格信息规则为基础，吸收参考项目中能增加策略空间的警长退水、狼人自爆、遗言和狼队协商流程，同时修正参考项目“配置声明与实际代码不一致”的部分。

推荐板子仍为：

```text
3 狼人 + 1 预言家 + 1 女巫 + 1 猎人 + 3 平民 = 9 人
```

参考项目把该配置称为“预女猎白板子”，但实际配置中没有白痴；若再加入白痴总人数会变成 10。因此 WolfScope 不采用这个名称，也不在 M1 加入白痴。

## 2. 核心规则对照

| 规则项 | 第一版 | 参考项目配置/README | 参考项目代码实际行为 | WolfScope 建议 |

| 九人角色 | 3狼、预女猎、3民 | 名称称“预女猎白”，数字实际为3狼、预女猎、3民 | 实际没有白痴 | 沿用第一版角色组成 |

## 3. 参考项目值得吸收的规则

### 3.1 狼队夜间协商

第一版只让决策源直接给出狼刀目标，参考项目会逐个收集狼人意见。WolfScope 应将其升级为明确协议：

```text
提案：每只狼给出目标、理由、置信度
  ↓
共享：仅狼队看到全部提案
  ↓
修订：每只狼可更新一次选择
  ↓
确认：多数决；平票按预先确定的轮值狼作最终决定
```

这比随机选择某只狼的目标更能体现协作、说服和策略一致性，也能评测狼队分歧率。

### 3.2 警长退水

参考项目允许候选人在竞选发言后退水。该机制能产生更丰富的身份判断：

- 真预言家是否坚持竞选
- 狼人悍跳后是否退水
- 退水时机是否暴露阵营关系

建议纳入 M1。

### 3.3 狼人自爆

自爆是有价值的策略行动，能测试 Agent 是否理解：

- 中止危险的白天讨论
- 保护狼队友
- 吞掉警徽或破坏警徽流
- 用自身死亡交换夜间节奏

但参考代码在自爆后直接把“存活好人列表”交给狼人，造成真实身份泄漏。WolfScope 只能提供存活座位和狼人已知信念。

M1 只支持基础自爆：狼人白天发言阶段可自爆，立即死亡并结束当天剩余发言和投票，进入夜晚。不实现双爆吞警徽和自爆指刀。

### 3.4 遗言

建议采用：

- 首夜死亡玩家有遗言
- 白天被放逐玩家有遗言
- 其他夜晚死亡默认无遗言
- 狼人自爆可发表一句自爆声明，但不再进行完整遗言

遗言属于公开发言事件，也应进入证据账本。

## 4. 不采用参考代码行为的部分

### 4.1 人数对等胜负

参考代码以 `wolf_count >= villager_count` 判狼人胜利，其中 `villager_count` 实际包含全部好人。这是“人数对等”规则，不是配置声明的“屠边”。

WolfScope 固定使用：

- 狼人全部死亡：好人胜
- 神职全部死亡：狼人屠神胜
- 平民全部死亡：狼人屠民胜

### 4.2 首夜不刀人

参考代码第一夜只让狼人互认，预言家仍可查验，狼人不刀人。这会给好人额外信息轮，并使首夜遗言配置失去意义。

WolfScope 首夜按正常夜晚结算。

### 4.3 随机解决警长平票和狼队分歧

随机选择警长或随机选择某只狼的目标会掩盖 Agent 的决策问题。WolfScope 使用明确、可记录、可测试的裁决协议；随机性只用于发牌和明确声明的兜底，并记录为 fallback。

### 4.4 配置存在但引擎不执行

参考项目的若干规则字段只是声明，没有稳定进入裁判逻辑。WolfScope 的 `RuleConfig` 每个字段必须满足：

1. 被引擎读取并执行；
2. 有至少一个正向测试和一个拒绝测试；
3. 写入 Replay 元数据；
4. 在 Prompt/策略库中与引擎规则一致。

否则不允许加入配置。

## 5. WolfScope 推荐规则基线 v0.1

### 5.1 板子与胜负

- 3 狼人、3 平民、预言家、女巫、猎人
- 好人屠狼胜；狼人屠神或屠民胜
- 同一结算点若狼人全灭且某个好人边也全灭，优先判好人胜

### 5.2 夜晚

- 首夜正常行动和结算
- 狼队必须选择一个存活目标，允许自刀
- 狼队通过结构化协商形成唯一目标
- 预言家每夜查验一名尚未查验过的存活其他玩家
- 查验结果为“狼人/好人阵营”，作为私密事件直接进入预言家的 `PlayerView`
- 查验结果同步写入预言家的 Evidence Ledger；好人结果不揭示具体神职或平民身份
- 女巫有一瓶解药和一瓶毒药
- 女巫不能自救，同夜不能救毒并用
- 解药存在时知道刀口；解药用完后不再知道刀口
- 猎人被刀可开枪，被毒不能开枪

### 5.3 警长

- 第一夜完成技能和死亡结算后，暂不向玩家公布死亡
- 先进行警长竞选，再公布首夜死亡
- 首夜待死亡玩家在死讯公布前不知道自己已被杀，仍可参与上警、竞选发言、退水和警长投票
- 上警发言后允许退水
- 竞选发言从 seed 固定的随机起点开始，沿座位顺序进行
- 报名和退水在游戏语义上同时决定，程序不得向后询问者泄露先前选择
- 仅警下玩家投票
- 最初报名者即使退水也不恢复警长竞选投票权
- 警长竞选允许弃票；全员弃票或无有效票则流警
- 单候选人直接当选
- 无有效票或平票则流警
- 警长放逐票为 1.5
- 警长决定白天发言方向并最后发言
- 警长死亡时可移交警徽或撕毁
- 基础自爆不允许在警长竞选期间使用

### 5.4 白天

- 每位存活玩家一轮主要发言
- 无警长时从 seed 固定的随机起点开始，按座位顺序发言
- 有警长时由警长选择顺时针或逆时针方向，警长最后发言
- 狼人仅可在自己的正常白天发言回合选择基础自爆；自爆后停止当日发言和投票，转入后续死亡链与夜晚流程
- 所有存活玩家可投票或弃票，不能自投
- 放逐投票在游戏语义上同时决定，后询问者不得看到先前票型
- 内部使用整数票权：普通玩家 2 单位，警长 3 单位，等价于 1 和 1.5 票
- 首轮平票后，平票者进行 PK 发言
- PK 发言沿原白天发言顺序过滤产生，不重新随机排序
- 平票者不参与重投
- 仅重投一次；重投仍平票或无有效票则当日无人出局
- 放逐 Observation 显式标注首轮或重投，Provider 不得通过候选人数猜测投票轮次
- 白天被放逐者有遗言
- 被放逐的猎人在遗言后进入开枪结算；猎人枪杀目标无遗言
- 警长被放逐或自爆时仅登记待处理警徽，实际移交或撕毁由 M1-5 统一结算
- 首夜死亡者有遗言，其余夜死无遗言

### 5.5 死亡链与胜负结算

- 夜间多人死亡属于同一死亡批次，先完整结算死亡技能，再判断胜负
- 首夜死亡名单在警长竞选后公布，首夜死者按座位号升序发表遗言；后续夜死无遗言
- 猎人被狼刀、放逐或猎人枪杀时可以开枪，也可以放弃；被毒时不能开枪
- 猎人只能选择另一名当前存活玩家，枪杀目标没有遗言
- 死亡警长在死亡技能结束后，可将警徽移交给当前存活玩家或撕毁警徽
- 若警长猎人死亡，顺序为遗言、猎人开枪、警徽处理
- 狼人自爆无遗言；若其持有警徽，仍进入基础警徽处理
- 非法猎人或警徽目标先拒绝并重试一次；再次失败时分别确定性兜底为不开枪或撕毁，且错误细节仅写入上帝事件
- 死亡链和警徽全部处理完成后统一检查胜负，中间状态不提前终止游戏
- 同一死亡批次同时满足狼人全灭与屠神或屠民时，好人胜利优先
- 游戏结束产生结构化公开事件，并在终局结果中统一公开全员身份

## 6. 已拍板的补充规则

1. **狼人自爆范围**：M1 只做基础自爆，不做双爆吞警徽和自爆指刀。
2. **警长竞选与首夜死讯顺序**：第一夜先完成内部结算，警长竞选结束后再公布死讯。
3. **预言家重复查验**：不允许验自己，也不允许重复查验；非法目标由协议拒绝并要求重选，重试失败后使用确定性合法目标兜底。

### 6.1 首夜待死亡状态

为避免在警长竞选前泄漏首夜结果，引擎区分：

- `pending_deaths`：上帝已经结算、尚未公开的首夜死亡
- `alive`：公开死讯宣布后才切换的正式存活状态

警长竞选期间：

- 所有玩家视图中都不能出现 `pending_deaths`
- 待死亡玩家本人也不知道自己将死亡
- 待死亡玩家仍具备警长竞选阶段的发言和投票资格
- 若待死亡玩家当选警长，死讯公布后立即触发警徽移交或撕毁
- 首夜被毒的猎人在死讯公布时死亡且不能开枪

### 6.2 预言家查验信息流

```text
预言家选择合法目标
  → 引擎读取真实阵营
  → 生成 PRIVATE(seer_seat) 的 seer_result 事件
  → 事件进入该预言家的 PlayerView
  → 感知层将其无损转换为 HARD_FACT Evidence
  → BeliefState 将目标的阵营概率固定为 wolf=1 或 good=1
```

查验属于确定性结构化事件，不调用信息抽取模型，也不依赖 LLM 从自然语言中重新提取。
